## 4. 最小处理方案与下一门禁

1. **POC 环境**：构建及真实 VM 创建期间保持一条长存活 WSL 会话；确认 Cube 控制/执行服务 `active`、Registry 可达且安全检查通过。不要把长睡眠作业作为生产 Cube 运维方案。
2. **状态对账**：对 RUNNING 超过可接受期限但 TemplateCenter 已无 Job 的状态按真实日志人工记录为 orphan。不可由 CLI 40% 推断“仍在构建”；对平台准入默认 Fail Closed。是否在上游修复 CubeMaster 的失败回调/reconciliation，属于依赖方技术问题，不在本 Harness 平台内自行实现 Cube 控制面。
3. **VM 启动故障**：对照已成功运行的原版 `sandbox-code` 模板，在相同 WSL 保活/节点 CPU/内存/事件超时下验证新模板的 Guest init/serial console、shim 收到 event 的耗时、envd 注入/probe 配置。必要时查 Cubelet/Containerd-shim 可配置的 10 秒 event timeout，而非不明原因直接放大生产超时值。
4. **严格准入**：复测真实模板达到 **READY** 后，再运行 `cubesandbox.Sandbox.create` + `commands.run('opencode --version')`、OpenCode 2 V2 HTTP Server、多 Session/FS/Shell/Git 和 Pydantic/OpenAI 同 Sandbox 接力；不得把 RootFS READY 误写成 Template READY。
5. 清理孤儿模板/构建产物前先核对 CubeMaster/Artifact 引用与状态，**本轮未清理或重置历史任务**。
